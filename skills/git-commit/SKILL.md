# Git Commit: 세이브 포인트 만들기

이 가이드는 코딩이 아니라 디자인 작업을 하는 사람이, 터미널 없이 VS Code의 Source Control 패널 버튼만 사용해서 세이브 포인트를 만드는 방법을 설명합니다.

작업하던 파일을 저장하는 것처럼, Git의 커밋은 게임에서 특정 시점의 저장 파일을 만드는 것과 비슷합니다. 지금까지 괜찮았던 상태를 남겨 두는 것이죠. 나중에 되돌아가거나, 다른 사람과 작업을 이어가거나, 실수해도 이전 상태로 복구할 수 있게 도와줍니다.

중요한 규칙:

> 항상, 작동하는 상태가 나오면 세이브 포인트를 만들기

작업이 잘 동작하는 순간을 남겨 두는 것이 가장 중요합니다. 실수로 무언가 깨졌을 때, 그 상태를 다시 되돌릴 수 있기 때문입니다.

## 1) 저장소 초기화: Repository를 시작하기

처음 프로젝트를 열었고 아직 Git 저장소가 아니라면 아래 순서로 진행합니다.

1. 왼쪽 사이드바에서 Source Control 아이콘을 누릅니다.
2. Initialize Repository 버튼을 찾습니다.
3. 버튼을 클릭합니다.
4. 잠시 뒤, 프로젝트 폴더가 Git 저장소로 등록됩니다.
5. 이 단계는 게임에서 새 파일을 저장할 수 있는 세이브 슬롯을 열어두는 것과 비슷합니다.

> 처음부터 저장소를 열어 두면, 지금까지의 작업을 안전하게 남길 수 있어요.

## 2) 변경 내용 확인: 어떤 상태가 바뀌었는지 보기

저장소가 준비되면 Source Control 패널에서 변경된 파일 목록을 확인합니다.

- 추가된 파일
- 수정된 파일
- 삭제된 파일

이 단계는 게임에서 현재 어떤 아이템이 추가됐고 어떤 장면이 바뀌었는지 점검하는 것과 같습니다.

1. Source Control 패널을 엽니다.
2. 변경 목록을 살펴봅니다.
3. 어떤 파일이 본인의 작업과 관련 있는지 확인합니다.
4. 필요하면 파일을 눌러 내용을 미리 확인합니다.

> 변경 내용을 확인하지 않고 저장하면, 원치 않는 부분까지 함께 남길 수 있어요.

## 3) 짧은 메시지 적기: 커밋 메시지 작성

커밋은 단순히 저장이 아니라, 어떤 이유로 저장했는지를 설명하는 메시지와 함께 남깁니다. 메시지는 짧고 분명하게 쓰는 것이 좋습니다.

예시:

- 초안 레이아웃 정리
- 상단 네비게이션 수정
- 메인 화면 색상 조정
- 텍스트 스타일 보완

좋은 메시지 원칙:

- 너무 길지 않게
- 무엇을 바꿨는지 알기 쉽게
- 다음에 다시 봤을 때 의미가 분명하게

> 커밋 메시지는 이 시점의 작업 내용을 기록하는 메모예요.

## 4) 커밋하기: 실제 세이브 포인트 저장

커밋을 만들 때는 Source Control 패널의 버튼을 사용합니다.

1. 변경한 파일을 확인합니다.
2. 커밋 메시지를 적습니다.
3. Commit 버튼을 누릅니다.
4. VS Code가 변경 내용을 저장소에 기록합니다.

이 순간이 바로 게임에서 세이브 포인트를 저장하는 순간입니다.

> 작동하는 상태를 남겨 두는 순간이에요. 나중에 다시 돌아오면 그 시점으로 복구할 수 있어요.

## 5) 동기화: 원격 저장소와 맞추기

작업을 클라우드나 팀 공유 환경에 반영하려면 동기화가 필요합니다. 보통 이 버튼을 사용합니다.

1. Source Control 패널을 엽니다.
2. 상단 또는 하단의 Sync 버튼을 찾습니다.
3. 버튼을 눌러 원격 저장소와 맞춥니다.

이 단계는 게임에서 세이브 파일을 클라우드에 올려 다른 기기에서도 이어받는 것과 비슷합니다.

> 로컬에서 잘 저장해 둔 상태를 다른 사람이나 다른 환경과 맞춰 주세요.

## 6) 되돌리기: 실수했을 때 복구하기

실수로 잘못 바꾼 경우, 다음 방법으로 되돌릴 수 있습니다.

### 방법 A: Discard Changes

- Source Control 패널에서 변경된 파일을 찾습니다.
- 해당 파일을 선택합니다.
- Discard Changes를 누릅니다.
- 최근 작업 내용을 취소합니다.

이건 게임에서 마지막으로 저장한 뒤의 작업을 한 번에 취소하는 기능과 비슷합니다.

> 작동하지 않는 상태를 만들었다면, 지금까지의 변경을 뒤로 돌릴 수 있어요.

### 방법 B: Timeline Restore Contents

- 파일을 선택하거나 해당 파일의 최신 변경 이력을 봅니다.
- Timeline 또는 변경 이력 보기 기능을 엽니다.
- 이전 시점의 내용을 선택합니다.
- Restore Contents 또는 비슷한 동작을 실행합니다.

이건 게임에서 이전 세이브 상태를 다시 불러오는 것과 비슷합니다.

> 특정 시점으로 돌아가고 싶다면, 그 저장 지점을 다시 불러오면 돼요.

## 7) 단어를 나중에 보게 될 때

이 가이드에서는 버튼만 사용하시면 됩니다. 하지만 나중에 Git 화면을 볼 때 아래 단어를 자주 보게 됩니다.

- 브랜치: 같은 프로젝트를 여러 갈래로 나눠서 작업하는 흐름
- 병합: 갈라진 작업을 하나로 합치는 것
- 원격: GitHub 같은 외부 저장소

이 단어들은 지금 당장 사용하지 않아도 됩니다. 지금 중요한 건 세이브 포인트를 남기는 습관입니다.

## 항상 기억할 규칙

### 골든 룰: 작동할 때마다 세이브 포인트를 만들기

- 기능이 정상적으로 보이는 순간
- 레이아웃이 안정적으로 보이는 순간
- 작업이 한 번 정리된 순간
- 실수로 뒤집기 전에 안전하게 남겨둘 때

이런 순간마다 커밋을 남기는 습관을 가지세요.

> 작동하는 상태를 남겨 두는 것이 가장 중요해요. 이후에 쓸 수 있는 안전한 지점이 생깁니다.

## Commands Used (버튼과 의미 매핑)

| VS Code 버튼 / 행동 | 실무 의미 | Git 관점 |
| --- | --- | --- |
| Initialize Repository | 저장소를 시작함 | git init |
| 파일 변경 목록 확인 | 어떤 파일이 수정됐는지 보기 | git status |
| + 또는 Stage 버튼 | 다음 커밋에 포함할 변경 선택 | git add |
| Commit 버튼 | 선택한 변경을 메시지와 함께 기록 | git commit |
| Sync 버튼 | 원격 저장소와 맞춤 | git push |

참고:

- VS Code의 버튼은 Git의 핵심 동작을 쉽게 보여주지만, 내부적으로는 Git이 실제로 처리합니다.
- 디자이너는 이 표를 외우기보다, 어떤 버튼을 눌러야 하는지 이해하는 데 집중하면 됩니다.

## Common Mistakes to Prevent (피해야 할 실수)

- 변경 내용을 확인하지 않고 바로 커밋하기
- 커밋 메시지를 비워 두거나 의미 없이 적기
- 마지막으로 잘되던 상태를 남기지 않고 계속 수정만 하기
- Sync 버튼을 지나치게 늦게 눌러 팀 상태와 로컬 상태가 어긋나게 만들기
- 실수했을 때 Discard Changes를 망설이다가 더 큰 변경을 남기기
- 작업 중인 상태를 저장하지 않고 나중에 복구할 수 있는 기준점을 만들지 않기

## 마지막으로

작업을 조금씩 쌓아 가는 건 게임에서 레벨을 저장하는 것과 같습니다. 매번 안정된 상태를 남겨 두면, 이후에 수정이 쉬워지고, 실수해도 다시 돌아갈 수 있습니다.

> 작은 세이브를 자주 남기는 습관이, 가장 안전한 작업 방식이에요.
