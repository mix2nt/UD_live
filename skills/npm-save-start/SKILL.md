# npm Save & Start: 부품 창고에서 시작하기

이 가이드는 코딩을 하지 않는 디자이너가, 터미널을 직접 쓰지 않고도 npm 설치, 빌드, 실행 흐름을 이해할 수 있도록 돕는 가이드입니다.

AI가 명령어를 대신 실행해 주고, 디자이너는 "무엇을 하고 있는지"를 이해하는 데 집중하면 됩니다.

## 창고 비유

프로젝트는 부품 창고와 비슷합니다.

- package = 부품
- install = 창고에 부품을 채우는 일
- build = 부품을 조립해서 완성품을 만드는 일
- watch = 자동으로 다시 조립해 주는 일

예를 들어, 플러그인 프로젝트는 여러 도구와 라이브러리를 필요로 합니다. 설치 단계는 "창고에 필요한 부품을 미리 비축하는 것"과 같습니다.

> "설치는 필요한 부품을 창고에 채우는 단계예요. 빌드는 그 부품으로 조립하는 단계예요."

## 1) 설치: 필요한 부품을 창고에 넣기

먼저 프로젝트가 필요한 패키지를 다운로드하고 준비합니다.

- npm install
- npm install --save-dev typescript @figma/plugin-typings

이렇게 하면 프로젝트에서 필요한 도구가 로컬 환경에 준비됩니다.

### 이렇게 이해하면 됩니다

- package는 부품입니다.
- install는 창고에 부품을 가져오는 작업입니다.
- 개발용 도구는 보통 save-dev로 추가합니다.

> "처음 프로젝트를 열면 필요한 부품을 비축해 두는 단계예요. 이 단계가 없으면 조립을 시작할 수 없어요."

## 2) 빌드: 조립해서 결과물 만들기

빌드는 소스 코드를 실제 실행 가능한 결과물로 바꾸는 단계입니다.

- npm run build

예시 의미:

- src/code.ts → dist/code.js

즉, 원본 코드를 브라우저나 Figma가 이해할 수 있는 형태로 바꾸는 과정입니다.

이 단계는 게임에서 "부품을 조립해서 완성된 장비를 만드는 것"과 비슷합니다.

> "빌드는 조립 단계예요. 소스 코드를 실제 실행할 수 있는 결과물로 바꾸는 과정이죠."

## 3) 실행: 실제로 테스트하기

실행은 보통 개발용으로 계속 감시하면서 작업하는 단계입니다.

- npm run watch

watch는 자동으로 다시 빌드해 줍니다. 그래서 코드를 수정한 뒤, Figma에서 다시 불러와서 바로 결과를 확인하는 흐름이 편해집니다.

> "watch는 자동으로 다시 조립해 주는 기능이에요. 수정하고 바로 다시 확인하는 데 좋아요."

## 4) edit, reload, look 반복

플러그인 작업의 핵심은 이 반복입니다.

1. 코드를 수정합니다.
2. Figma에서 다시 불러옵니다.
3. 결과를 확인합니다.
4. 다시 수정합니다.

이 루프를 간단히 말하면:

- edit: 수정
- reload: 다시 불러오기
- look: 확인

이 단계는 게임에서 "장비를 바꾸고, 다시 실행해 보고, 결과를 확인하는 것"과 비슷합니다.

> "수정하고 다시 불러오고 확인하는 반복이 핵심이에요. 이 루프를 익히면 가장 빠르게 작업할 수 있어요."

## 5) manifest.json이 어디를 가리키는지

플러그인 설정 파일인 manifest.json은 실제 실행 코드의 위치를 가리킵니다.

- manifest.json → dist/code.js

즉, Figma는 코드 파일을 직접 읽는 대신, manifest에서 어떤 JS 파일을 실행할지 찾습니다.

이것은 공장 지시서가 "완성된 제품은 여기에서 꺼내라"고 알려주는 것과 비슷합니다.

> "manifest.json은 실제 실행 파일이 어디 있는지를 알려주는 안내서예요. 보통 dist/code.js를 가리킵니다."

## 6) node_modules는 건드리지 않기

node_modules 폴더는 자동으로 설치되는 라이브러리 보관 창고입니다. 보통 디자이너는 직접 여기 안을 만지지 않습니다.

- 건드리지 않기
- 파일을 수동으로 삭제하지 않기
- 패키지 설치를 직접 조작하지 않기

문제가 생기면, 어떤 오류 메시지가 나왔는지 그대로 AI에게 복사해서 전달하면 됩니다.

> "node_modules는 자동으로 관리되는 창고예요. 직접 만지지 않는 게 안전해요. 에러는 그대로 보내주면 AI가 확인해 줍니다."

## Commands Used

| 명령 | 의미 | 비유 |
| --- | --- | --- |
| npm install | 필요한 패키지를 설치함 | 창고에 부품을 채우기 |
| npm install --save-dev typescript @figma/plugin-typings | 개발용 도구를 추가함 | 개발용 도구 부품 비축 |
| npm run build | 소스를 결과물로 조립함 | 완성품으로 조립하기 |
| npm run watch | 코드를 수정하면 자동으로 다시 조립함 | 자동 재조립 모드 |

## 핵심 요약

- package = 부품
- install = 창고에 부품 채우기
- build = 조립
- watch = 자동 재조립
- manifest.json = 실행 파일 위치 안내서
- edit → reload → look = 핵심 반복 루프

## Common Mistakes to Prevent (피해야 할 실수)

- 설치 전에 필요한 패키지가 준비됐는지 확인하지 않기
- build를 실행하지 않고 결과를 기대하기
- watch를 켜지 않은 상태에서 수정 내용을 확인하려고 하기
- node_modules를 직접 건드려서 환경이 깨지게 만들기
- 에러 메시지를 AI에게 그대로 전달하지 않고 추측으로 해결하려고 하기
- manifest.json이 dist/code.js를 가리키는 구조를 이해하지 않고 수정하기

## 마지막으로

이 과정은 코드 작업을 위한 준비 단계이지만, 디자이너에게 중요한 건 "무엇을 하고 있는지 이해하는 것"입니다.

부품 창고를 채우고, 조립하고, 다시 확인하는 흐름만 익히면 됩니다.

> "설치, 빌드, 실행은 모두 작업을 안정적으로 준비하는 단계예요. 곧장 결과를 보려면 이 흐름을 따라가면 됩니다."
