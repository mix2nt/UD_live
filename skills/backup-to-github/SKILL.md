# GitHub Backup: 온라인 백업으로 올리기

이 가이드는 코딩을 하지 않는 디자이너가, 터미널 없이 VS Code의 버튼만 사용해서 자신의 코드를 GitHub에 백업하는 방법을 설명합니다.

중요: 이 작업은 웹사이트를 실제로 인터넷에 공개하는 것과 다릅니다. Figma 플러그인은 Figma 안에서 실행되는 도구이고, 웹 서버가 없습니다. 그래서 이건 "호스팅"이 아니라 "코드 백업 + 공유"입니다.

> 이건 Vercel, Netlify 같은 웹 호스팅이 아닙니다. 여기서는 코드를 GitHub에 올려 두는 행위예요.

## 클라우드 폴더 비유

GitHub를 생각할 때는 컴퓨터 안의 폴더를 인터넷 클라우드 폴더로 옮기는 느낌이라고 보면 됩니다.

- 로컬 컴퓨터: 내 작업 공간
- GitHub: 인터넷에 보관되는 안전한 클라우드 폴더
- 커밋: 폴더 안에 중요한 시점의 상태를 남기는 저장 포인트
- Sync / Publish Branch: 클라우드 폴더에 업로드하는 행위

게임에서 세이브 파일을 클라우드에 올려 다른 기기에서도 이어서 할 수 있는 것처럼, GitHub도 같은 역할을 합니다.

> "내 작업을 컴퓨터 안에만 두는 것보다, 클라우드 폴더에 안전하게 남겨 두는 편이 좋아요."

## 1) 저장소 만들기: GitHub에 올릴 준비

먼저 GitHub 계정에 저장소를 만듭니다. 이 단계는 VS Code 안에서 바로 진행할 수도 있지만, 보통 GitHub 웹사이트에서 만드는 것이 가장 쉽습니다.

1. GitHub에 로그인합니다.
2. 새 저장소를 만듭니다.
3. 저장소 이름을 정합니다.
4. 공개 여부를 선택합니다.
5. README를 나중에 추가할 수도 있으니, 처음엔 비워 두어도 괜찮습니다.

> "처음에는 작동하는 코드만 안전하게 올려 두는 게 좋아요. 공개 여부는 나중에 결정해도 됩니다."

## 2) Publish Branch: 처음 업로드

코드를 GitHub에 올리는 첫 단계는 Publish Branch입니다. 이 버튼을 누르면 로컬 작업 내용을 원격 저장소로 보냅니다.

1. VS Code 왼쪽 사이드바에서 Source Control을 엽니다.
2. 변경된 파일을 확인합니다.
3. 커밋 메시지를 적습니다.
4. Publish Branch 버튼을 누릅니다.
5. GitHub 저장소를 선택합니다.
6. 브랜치 이름을 확인합니다.

이 단계는 게임에서 "내 현재 진행 상태를 클라우드 세이브 슬롯에 올리는 것"과 비슷합니다.

> "처음 업로드는 '안전하게 백업해 두는 단계'예요. 공개 여부와는 별개로 진행합니다."

## 3) Sync: 지금 상태를 맞추기

작업이 끝날 때마다 또는 자주, Sync 버튼을 눌러 로컬 작업과 GitHub 상태를 맞춥니다.

1. Source Control 패널을 엽니다.
2. 커밋이 남아 있으면 확인합니다.
3. Sync 버튼을 누릅니다.
4. GitHub에 반영된 최신 상태를 확인합니다.

이 단계는 게임에서 "세이브를 정기적으로 클라우드에 저장하는 것"과 비슷합니다.

> "작업이 조금씩 쌓이면, 꼭 Sync해서 안전하게 동기화해 주세요."

## 4) Week 5에서 공개로 바꾸기

처음에는 보통 비공개 상태로 두는 것이 안전합니다. 프로젝트가 어느 정도 정리되고, 공유해도 괜찮은 상태가 되면 공개로 바꾸면 됩니다.

1. GitHub 저장소 페이지를 엽니다.
2. 저장소 설정으로 이동합니다.
3. Visibility 또는 Repository visibility를 확인합니다.
4. Public으로 변경합니다.
5. 필요하면 링크를 공유합니다.

이 단계는 게임에서 "나중에 공개 테스트용 세이브를 다른 사람에게 보여주는 것"과 비슷합니다.

> "처음부터 공개로 두지 않아도 돼요. 작업이 안정적일 때 공개로 바꾸면 됩니다."

## 5) README 추가하기

공개할 준비가 되면 README를 추가해서 프로젝트를 설명해 주세요.

- 무엇을 만드는 프로젝트인지
- 어떤 파일이 들어 있는지
- 누가 이 코드를 볼 수 있는지
- 작업 상태 또는 메모

README는 프로젝트의 카드 설명서처럼 동작합니다.

> "README는 저장소를 열어 본 사람이 어떤 프로젝트인지 이해하게 해주는 설명서예요."

## Not Vercel: 호스팅이 아니라 백업입니다

이 가이드는 웹 호스팅이 아닙니다. Figma 플러그인은 웹 서버를 직접 돌릴 수 없는 구조라서, 이 작업은 웹사이트를 공개하는 것이 아니라 코드 저장소를 안전하게 백업하고 공유하는 행위로 이해해야 합니다.

- Vercel/Netlify: 웹사이트를 실제로 인터넷에서 실행하는 서비스
- GitHub 백업: 코드와 파일을 안전하게 보관하는 저장소
- 이 스킬: 코드 백업 + 공유용 흐름

웹사이트를 공개하고 싶다면, 그건 별도의 단계로 다루는 주제입니다. 여기서는 "코드 업로드와 안전 보관"이 핵심입니다.

> "여기는 웹사이트를 배포하는 도구가 아니라, 코드를 안전하게 올려두는 백업 공간이에요."

## GitHub 백업 vs Figma Community 공개 비교

| 항목 | GitHub 백업 | Figma Community 공개 |
| --- | --- | --- |
| 목적 | 코드 보관, 공유, 버전 관리 | 디자인 결과물 공개 |
| 사용 대상 | 코드 파일, 프로젝트 저장소 | Figma 파일, 디자인 결과 |
| 웹 서버 필요 여부 | 아니요 | 아니요 |
| 실제 실행 환경 | GitHub 저장소 | Figma 캔버스 / 커뮤니티 페이지 |
| 디자이너가 이해해야 할 핵심 | 백업과 공유 | 공개와 시각적 설명 |
| 이 가이드의 포커스 | 코드 안전 보관 | 디자인 공개 |

중요한 점:

- 둘 다 "공유"의 성격이 있지만, 목적과 의미는 다릅니다.
- GitHub는 코드 백업이며, Figma Community는 디자인 결과 공개입니다.

## Commands Used (버튼과 의미 매핑)

| 버튼/행동 | 의미 | Git 관점 |
| --- | --- | --- |
| Initialize Repository | 로컬 저장소 준비 | git init |
| Commit 버튼 | 현재 상태를 기록 | git commit |
| Publish Branch 버튼 | GitHub에 첫 업로드 | git push -u origin main |
| Sync 버튼 | 로컬과 원격 최신 상태 맞춤 | git pull / git push |
| README 추가 | 프로젝트 설명 문서 작성 | 파일 추가 + 커밋 |

참고:

- UI 버튼은 Git의 기본 동작을 쉽게 보여주는 방식입니다.
- 디자이너는 내부 명령어를 외우기보다, 어떤 버튼을 누르면 어떤 결과가 생기는지 이해하는 데 집중하면 됩니다.

## Common Mistakes to Prevent (피해야 할 실수)

- 웹 호스팅과 GitHub 백업을 같은 의미로 혼동하기
- 공개 전까지 비공개 상태를 놓치고 바로 공개로 올리기
- README 없이 저장소만 올려서 무엇을 담은 프로젝트인지 설명하지 않기
- Sync를 자주 안 해서 로컬 상태와 GitHub 상태가 어긋나게 만들기
- 작업이 안정화되기 전에 커밋 메시지를 의미 없이 남기기
- 다른 사람에게 코드 링크를 넘기기 전에 저장소가 실제로 연결됐는지 확인하지 않기

## 권장 흐름 요약

1. 작업이 어느 정도 정리되면 커밋합니다.
2. Publish Branch로 GitHub에 처음 올립니다.
3. 이후에는 Sync로 계속 맞춥니다.
4. 프로젝트가 안정되면 Week 5처럼 공개로 전환합니다.
5. README를 추가해 설명서를 남깁니다.

> "작업이 안정되면 백업하고, 나중에 공유하면 됩니다. 공개 전에는 비공개로 두는 게 안전해요."

## 마지막으로

GitHub는 게임에서 "세이브 파일을 온라인 클라우드에 보관하는 것"과 비슷합니다. 중요한 건 웹사이트를 배포하는 게 아니라, 작업을 안전하게 보관하고 나중에 다시 이어받을 수 있게 만드는 것입니다.

> "백업은 실수를 줄이고, 나중에 다시 시작할 수 있게 만들어요."
